De-Para: o que mudou

Comparação lado a lado entre o estado inicial do repositório e o estado final após a execução.

Antes

Bot do Telegram fortemente acoplado ao provedor: o worker inteiro falava grammY e Telegram diretamente.

  • worker/command/router.ts com 1.039 linhas: roteador de comandos e acionador de sendMessage do grammY
  • worker/lib/{client,polling,keyboard,token,transport-log,auto-retry,outbox}.ts — infraestrutura telegram-específica embutida no worker
  • worker/auth/** com allowlist de ids do Telegram acoplada ao formato <user>:<chat>
  • IDs fluíam como strings de telegram no IPC; envelope V1 numérico montado no host
  • Nenhuma forma de adicionar outro provedor sem reescrever o worker
  • Sem manual de provedores, sem skill de contribuição, CONTRIBUTING.md §0 dizia que o bot "ainda não existe"
Depois

Arquitetura de provedores plugáveis: núcleo neutro + adaptadores por provedor + boot genérico.

  • worker/surface/** — núcleo de mensageria 100% neutro (contract/cores/auth/commands/outbox)
  • worker/providers/telegram/** — adaptador do provedor atual; worker/providers/registry.ts resolve por DSH_GUARD_PROVIDER
  • Adicionar um provedor = criar worker/providers/<novo>/ + registar no registry + config — sem tocar no núcleo
  • IDs como strings na fronteira (D4), cast numérico concentrado na SurfaceIpcBridge
  • ENV allowlist por provedor; token opaco S5; exit codes 10–14 preservados
  • docs/PROVIDERS.md (manual completo), 2 skills em .agents/skills/, CONTRIBUTING.md corrigido e com secção de provedores

Impacto

O que cada mudança significa para quem usa o deep-orchestrator-agent-skill:

Provedores plugáveis — o worker de mensageria passou a ser agnóstico: worker/surface (núcleo neutro) + worker/providers/<provedor> (adaptador) + registry resolvido por DSH_GUARD_PROVIDER. Adicionar WhatsApp/Discord/Signal = novo diretório de adaptador + registo, sem tocar no núcleo.
Zero novas dependências runtime (decidido em D6): grammY 1.45.1 continua a única dependência; o núcleo neutro não importa nada de provedor.
−10.993 linhas de worker legado — roteador de 1.039 linhas, auth telegram-específica e infraestrutura lib/* eliminadas; o contrato vive agora em worker/surface/contract.ts (+506) e o cone de import §5.5 é garantido por teste estrutural.
Segurança preservada invariante a invariante — allowlist 2 eixos default-deny (TG-007), ids-string na fronteira, nunca username, S5 token/nonce opacos, S4 nunca lançar no handler, exit codes 10/11/12/13/14/0; canário ADV-055 atualizado para aceitar o novo rótulo DSH_GUARD_PROVIDER.
Manual + skills para contribuidores — docs/PROVIDERS.md vira manual completo (passo-a-passo para provedor novo); .agents/skills/dsh-provider-bot (genérica, fonte do contrato) e dsh-telegram-provider (específica grammY); CONTRIBUTING.md corrigido (§0 agora verdadeiro) e com secção de provedores.
Comportamento do bot inalterado para o utilizador — a entrada continua worker/telegram-bot (nome legado, D1/D13), variável continua TELEGRAM_BOT_TOKEN, TELEGRAM_API_ROOT respeitado; default worker.provider: telegram no schema e cordis.patch.yml.
/rotacionar mais seguro — além de revogar a chave e as sessões, a rotação encerra agora TODAS as conexões abertas sob o acesso antigo (WebSocket 101 e streams em voo) via encerrarConexoesAtivas() em src/tunnel/proxy.ts; a ordem é fail-closed (sessões → chave → encerramento) e o listener do proxy NÃO é derrubado.

Novas capacidades

Adapter ProviderAdapter

Contrato ProviderAdapter completo (id/limits/start(handleEvent)/stop/publishCommands/sender) — qualquer provedor cumpre o mesmo contrato.

Registry + resolver fail-closed

resolverProvedor(env) lê DSH_GUARD_PROVIDER; desconhecido recusa o arranque com erro claro.

SurfaceEvent discriminado

comando | acao | acao-invalida com answerTarget obrigatório (TG-027) — o núcleo decide, o adaptador responde sempre.

SurfaceLimits por canal

4096 bytes texto / 1 linha / 1 ação por linha / 64 bytes dados / edição — telegram cumpre; outro provedor declara os seus.

SurfaceIdentity string (D4)

userKey/chatKey strings neutras; o cast numérico do envelope IPC V1 fica concentrado na SurfaceIpcBridge.

Manual + skills de contribuição

docs/PROVIDERS.md + 2 skills em .agents/skills/ — o caminho "adicionar provedor" está documentado fim-a-fim.

encerrarConexoesAtivas()

Método novo no contrato TunnelProxy: síncrono, idempotente, destroy nos sockets rastreados; o /rotacionar encerra as conexões sob o acesso antigo sem derrubar o listener.

Premissas inferidas sem perguntar

O orquestrador opera em autonomia total — nenhuma pergunta é feita ao usuário. Toda premissa assumida fica registrada aqui — para revisão e reprodutibilidade.

  • D1/D13
    Entrada preserva o nome legado — worker/telegram-bot continua sendo a entrada (pinned por WORKER_ENTRY_BASENAME + tsconfig.worker.json); o conteúdo é o boot genérico.
  • D2
    Tabelas duplicadas host/worker — a tabela de provedores existe no host (src/proc/env.ts allowlist) e no worker (worker/providers/registry.ts); acoplamento por convenção de env var, sem import entre mundos.
  • D3
    provider? aditivo no estado v1 — campo opcional no schema; persistências antigas continuam válidas (default telegram).
  • D4
    Identidade como strings na fronteira — SurfaceIdentity.userKey/chatKey; o cast para Number do IPC V1 acontece só dentro de montarEnvelopeDeIntent na bridge.
  • D6
    Zero novas dependências — grammY 1.45.1 permanece a única dependência runtime; adaptadores futuros trazem as suas.
  • 5a
    Ganhador do conflito de merge onda 5a — montarEnvelopeDeIntent/IntencaoNeutra re-pousados na criarSurfaceIpcBridge (design 5a) após resolução adversarial em subagente dedicado (commit 29bcc2a).
  • IRC
    Gates de snapshot em paralelo — gate de cada squash roda no snapshot int-ondaN-* enquanto os merges seguintes avançam; o verde de cada um precede a limpeza da sua onda (R6/F3-01).
  • flake
    Classificação de ruído — 3 testes temporizados pré-existentes (commits de 2026-08-20, anteriores à worktree) ficam vermelhos sob carga da máquina e passam isolados; re-registrados como ruído ambiente em todas as ondas, nunca como regressão das ondas.
  • /rotacionar
    Ordem do rotate é contrato (integração com main) — sessoes + chave caem ANTES do encerramento das conexões (fail-closed); o rastreio manual de sockets (server.on('connection')) é obrigatório porque closeAllConnections do Node não fecha sockets upgraded; o listener do proxy permanece para a chave nova.
